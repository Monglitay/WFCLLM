# calibrate 自主补充负样本

历史实现要求外部预先备好负样本语料并通过参数传入 `calibrate`，语料缺失时该阶段直接跳过校准。我们改为让 `calibrate` 在语料不足或缺失时，自行从同一生成模型产出未加水印的补全来补齐。手稿的表述本就是「在留出的未加水印生成上按目标假阳率校准」，负样本是模型的未加水印生成，而不是一份外部资产。

## Consequences

- 目标负样本数由配置给出，补齐后的语料须记录来源构成：外部提供多少条、自动生成多少条、生成所用模型与解码配置。该构成进入校准产物，使阈值可追溯到具体的负样本集合。
- 负样本必须与正样本评测集不重叠。「留出」是硬要求 —— 若补充过程从正样本用过的提示上生成，校准就失去意义。
- 补充过程不得使用 pass、测试或正确性代理做筛选，这是仓库对校准阶段的既有禁令。生成即采用。
- 负样本语料指纹字段继续保留，但须覆盖补齐后的完整语料，使校准产物与其负样本一一对应。
- 校准阶段从此需要生成模型在位，不再是纯读文件的轻量阶段；`calibrate` 的资源需求向 `generate` 靠拢。
- 这项改动同时修掉一个统计问题：历史 run 的负样本数只有数十条量级，最细假阳率粒度就是负样本数的倒数，无法可靠地把阈值校准到手稿要求的目标假阳率上。自主补齐使目标负样本数成为可配置量，而不是受制于手头恰好有多少条预制样本。
