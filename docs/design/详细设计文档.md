# WFCLLM 详细设计文档

> 项目全称：基于语句块语义特征的生成时代码水印系统（WaterMark for Code LLM）

---

## 1. 系统概述

### 1.1 系统简介

WFCLLM（WaterMark for Code LLM）是一个面向大语言模型（LLM）生成代码的**生成时不可见水印系统**。随着 GPT-4、CodeLlama 等代码大模型的广泛应用，AI 生成代码的溯源与确权成为重要问题。

本系统以代码抽象语法树（AST）的语句块为最小嵌入单元，通过三个阶段完成水印的全生命周期管理：

- **阶段一**：以对比学习微调 CodeT5，训练对代码等价变换具有不变性的鲁棒语义编码器
- **阶段二**：在 LLM 生成代码时，实时拦截语句块，通过拒绝采样将水印信息隐式嵌入语义特征
- **阶段三**：在不依赖原始代码的情况下，通过动态规划去重与 Z-score 假设检验完成水印检测

### 1.2 术语表

| 序号 | 术语或缩略语 | 说明性定义 |
|------|-------------|-----------|
| 1 | LLM | Large Language Model，大语言模型 |
| 2 | AST | Abstract Syntax Tree，抽象语法树，代码的树形结构表示 |
| 3 | 语句块（Statement Block） | AST 中的最小可嵌入单元，分为简单语句块（simple）和复杂语句块（complex） |
| 4 | 语义编码器（Semantic Encoder） | 基于 CodeT5 对比学习微调的代码语义特征提取模型，输出 128 维向量 |
| 5 | LSH | Locality Sensitive Hashing，局部敏感哈希，将高维向量映射到低维哈希位 |
| 6 | 方向向量（Direction Vector） | 由密钥与 AST 局部拓扑哈希派生的伪随机单位向量，决定水印嵌入方向 |
| 7 | 拒绝采样（Rejection Sampling） | 对不满足水印条件的代码块触发重新生成，直至满足条件或达到重试上限 |
| 8 | KV-Cache | Transformer 的键值缓存，用于高效回滚生成状态至语句块起始位置 |
| 9 | 节点信息熵（Node Entropy） | 衡量 AST 节点生成不确定性的指标，用于动态调整水印嵌入裕度 |
| 10 | 动态裕度（Dynamic Margin） | 由节点熵决定的余弦投影最小阈值，低熵节点裕度小，高熵节点裕度大 |
| 11 | DP 去重 | 动态规划去重，自底向上遍历 AST 消除嵌套节点的统计相关性 |
| 12 | Z-score | 标准化统计量，用于假设检验判断水印是否存在 |
| 13 | BlockContract | 语句块契约，嵌入端与提取端共享的不可变元数据结构 |
| 14 | 嵌入率（Embed Rate） | embedded_blocks / total_blocks，衡量水印嵌入成功比例 |
| 15 | 自适应 Gamma | 根据节点熵分位数动态调整 LSH 投影阈值 γ 的机制 |
| 16 | Token 通道 | 辅助水印通道，在 token 概率分布层面叠加水印信号 |
| 17 | LoRA | Low-Rank Adaptation，参数高效微调方法，仅训练低秩矩阵 |
| 18 | FPR | False Positive Rate，误报率，未加水印代码被误判为含水印的概率 |
| 19 | TPR | True Positive Rate，检出率，含水印代码被正确检测的概率 |
| 20 | JSONL | JSON Lines，每行一个 JSON 对象的文本格式，用于流式数据存储 |

### 2.3 数据结构

#### BlockContract（语句块契约）

**功能说明：** 嵌入端与提取端共享的不可变语句块元数据，是系统的核心数据契约。

**所在文件：** `wfcllm/common/block_contract.py`

```python
@dataclass(frozen=True)
class BlockContract:
    ordinal: int            # 块在代码中的顺序编号（0-indexed）
    block_id: str           # 唯一标识符（UUID 格式）
    node_type: str          # AST 节点类型，如 "if_statement", "for_statement"
    parent_node_type: str | None  # 父节点类型，用于密钥派生；顶层块为 "module"
    block_text_hash: str    # 块源文本 SHA-256 哈希（64 字符十六进制）
    start_line: int         # 块起始行号（1-indexed）
    end_line: int           # 块结束行号（1-indexed，含）
    entropy_units: int      # 节点信息熵单元数（加权 token 数量）
    gamma_target: float     # 目标 LSH 阈值 γ（自适应模式下由熵分位数决定）
    k: int                  # 分位数桶索引（自适应模式）
    gamma_effective: float  # 实际使用的 γ 值（固定模式下等于 lsh_gamma）
```

#### WatermarkConfig（水印嵌入配置）

**功能说明：** 水印嵌入阶段的全部超参数，通过 JSON 配置文件或 CLI 参数传入。

**所在文件：** `wfcllm/watermark/config.py`

```python
@dataclass
class WatermarkConfig:
    secret_key: str               # 水印密钥（不持久化）
    encoder_model_path: str       # 语义编码器本地路径或 HF Hub ID
    encoder_embed_dim: int        # 语义向量维度，默认 128
    margin_base: float            # 基础裕度 m_base，默认 0.1
    margin_alpha: float           # 裕度缩放系数 α，默认 0.05
    max_retries: int              # 最大重试次数，默认 5
    temperature: float            # 采样温度，默认 0.8
    top_p: float                  # nucleus sampling 阈值，默认 0.95
    top_k: int                    # top-k 采样，默认 50
    max_new_tokens: int           # 最大生成 token 数，默认 512
    lsh_d: int                    # LSH 哈希函数数量，默认 3
    lsh_gamma: float              # LSH 投影阈值 γ，默认 0.5
    lsh_whitening_path: str|None  # ZCA 白化矩阵路径，None 表示禁用

    retry_temperature_schedule: list[tuple[int, float]] | None  # 重试温度调度
    use_ordinal_keying: bool      # 是否在密钥派生中加入块序号，默认 False
```

**模块间调用关系：**

- CLI 层通过 `runners.py` 构建各阶段 Config 对象，调用编排层 `PhaseOrchestrator`
- 编排层按 DAG 顺序调度三个业务模块，通过 `RunStateManager` 记录完成状态
- 水印嵌入模块调用 `lang/python/parser.py` 进行实时 AST 解析
- 水印嵌入与提取模块共享 `common/block_contract.py` 的 `build_block_contracts()` 函数
- 编码器模块训练完成后，权重路径写入配置，供嵌入/提取模块加载

### 3.2 功能设计说明

系统采用**三阶段流水线 + 双通道水印**的核心设计：

**三阶段流水线：** 编码器预训练（阶段一）→ 生成时嵌入（阶段二）→ 提取验证（阶段三）。三个阶段通过 `BlockContract` 数据契约解耦，嵌入端将契约序列化到 JSONL 文件，提取端读取后重建相同的验证参数，保证两端一致性。

**双通道水印：** 主通道（语义通道）基于代码块整体语义特征进行水印嵌入，对等价变换攻击具有鲁棒性；辅助通道（Token 通道）在 token 概率分布层面叠加水印信号，两者可独立启用或联合使用。

**层次化兜底：** 简单语句块级别重试（最多 `max_retries` 次）→ 级联回退到外层复杂语句块整体重试，保证整体嵌入率。

### 3.3 语义编码器模块（`wfcllm/encoder/`）

#### 3.3.1 设计图

```
数据集(HumanEval/MBPP)
        │
        ▼
  语句块分割(tree-sitter)
        ├──→ 正变换引擎 ──→ 正样本 x+（等价变换）
        └──→ 负变换引擎 ──→ 负样本 x-（破坏性变换 + 随机无关块）
        │
        ▼
  三元组 (x, x+, x-) → CodeT5-base + LoRA → Margin Loss → 编码器 E
```

#### 3.3.2 功能描述

训练对代码等价变换具有不变性的语义特征提取器。以 CodeT5-base 为骨干，通过 LoRA 参数高效微调，使编码器满足：对等价变换后的代码输出相似向量（余弦相似度高），对语义破坏性变换后的代码输出差异向量（余弦相似度低）。

#### 3.3.3 输入数据

| 数据项 | 来源 | 格式 | 有效性规则 |
|--------|------|------|-----------|
| 原始代码块 x | HumanEval/MBPP 数据集 | Python 代码字符串 | 长度 ≤ 256 token，可被 tree-sitter 解析 |
| 正样本 x+ | AST 等价变换引擎 | Python 代码字符串 | 与 x 语义等价，AST 结构不同 |
| 负样本 x- | 破坏性变换 + 随机采样 | Python 代码字符串 | 与 x 语义不等价 |
| 训练配置 | `EncoderConfig` dataclass | Python dataclass | 所有数值参数需在合理范围内 |

#### 3.3.4 输出数据

| 数据项 | 格式 | 说明 |
|--------|------|------|
| 编码器权重 | PyTorch `.pt` 文件 | 保存至 `data/models/encoder/` |
| 训练检查点 | PyTorch `.pt` 文件 | 保存至 `data/checkpoints/encoder/` |
| 评估指标 | JSON 文件 | top-1/top-5 检索准确率、验证集损失 |
| 语义向量（推理时） | `torch.Tensor [128]` | L2 归一化，供嵌入/提取模块使用 |

#### 3.3.5 数据设计

```python
# 训练批次结构
class TrainingBatch:
    anchor_ids: Tensor      # [B, seq_len] 原始代码 token IDs
    positive_ids: Tensor    # [B, seq_len] 正样本 token IDs
    negative_ids: Tensor    # [B, seq_len] 负样本 token IDs
    # 对应的 attention mask 各一份
```

检查点文件名格式：`encoder_epoch{N}_loss{L:.4f}.pt`，存于 `data/checkpoints/encoder/`。

#### 3.3.6 算法和流程

**边界损失函数：**

$$L = \sum_{i} \max\{0,\ \delta - \cos(E(x_i), E(x_i^+)) + \cos(E(x_i), E(x_i^-))\}$$

其中 $\delta = 0.3$（`margin` 参数），$E(\cdot)$ 为编码器输出的 L2 归一化向量。

**训练流程：**

```
1. 初始化 CodeT5-base + LoRA（仅 Q/V 注意力矩阵）
2. for epoch in range(epochs):
   a. 采样语句块，构造三元组：
      - 正样本：随机选一种等价变换规则应用于 x
      - 负样本：以 negative_ratio 比例混合困难负样本和随机无关块
   b. 前向传播：编码 x, x+, x- → 向量 u, u+, u-
   c. 计算 Margin Loss，反向传播更新 LoRA 参数
   d. 验证集评估，连续 early_stopping_patience 轮无改善则停止
3. 导出最优检查点到 output_model_dir
```

#### 3.3.7 函数说明

| 函数名 | 所在文件 | 功能 | 参数 | 返回值 |
|--------|---------|------|------|--------|
| `SemanticEncoder.encode` | `encoder/model.py` | 提取语义向量 | `code: str` | `Tensor[128]`（L2 归一化） |
| `EncoderTrainer.train` | `encoder/trainer.py` | 执行完整训练 | `config: EncoderConfig` | `Path`（最优检查点路径） |
| `EncoderEvaluator.evaluate` | `encoder/evaluate.py` | 评估检索准确率 | `test_dataset, encoder` | `dict`（top-k 准确率） |
| `ContrastiveDataset.__getitem__` | `encoder/dataset.py` | 构造训练三元组 | `idx: int` | `TrainingBatch` |

#### 3.3.8 全局数据结构与该模块的关系

- 读取：`EncoderConfig`（模型路径、超参数）
- 写入：编码器权重文件（`WatermarkConfig.encoder_model_path` 引用该路径）
- 不直接访问：`BlockContract`（由上层负责语句块分割）

### 3.4 水印嵌入模块（`wfcllm/watermark/`）

#### 3.4.1 设计图

```
LLM 生成循环（token 流）
        │
        ▼
WatermarkInterceptor
（挂载在生成循环上，检测简单语句块闭合）
        │ 触发
        ▼
SemanticChannel：
  1. 提取 AST 局部拓扑哈希（parent_type + node_type）
  2. 密钥派生 → 方向向量 v 和目标位 t
  3. 节点熵计算 → 动态裕度 m
  4. encoder.encode(block) → 语义向量 u
  5. p = cos(u,v)；验证 sgn(p)==t* 且 |p|>m
        │ 失败
        ▼
KVCacheManager.rollback() → 重试（≤ max_retries）
        │ 重试耗尽
        ▼
CascadeHandler → 等待外层复杂块闭合，整体重试
        │
        ▼
WatermarkPipeline → 写入 JSONL 结果文件
```

#### 3.4.2 功能描述

在 LLM 生成代码时，以语句块为粒度实时嵌入水印。核心是拒绝采样：若当前生成的代码块不满足水印条件，通过 KV-Cache 回滚重新生成，直至满足条件或达到重试上限；仍失败则由级联兜底机制处理外层复杂块。

#### 3.4.3 输入数据

| 数据项 | 来源 | 格式 | 有效性规则 |
|--------|------|------|-----------|
| 代码生成提示 | 数据集或用户输入 | 字符串 | 非空 |
| `WatermarkConfig` | 配置文件/CLI | Python dataclass | `secret_key` 非空，各数值参数合理 |
| LLM 模型权重 | 本地路径或 HF Hub | HuggingFace 格式 | 路径存在且可加载 |
| 编码器权重 | `encoder_model_path` | PyTorch `.pt` | 路径存在，`embed_dim` 匹配 |

#### 3.4.4 输出数据

| 数据项 | 格式 | 说明 |
|--------|------|------|
| 带水印代码 | 字符串 | 功能正确，含隐式水印 |
| `GenerationResult` | Python dataclass | 含嵌入统计和 `BlockContract` 列表 |
| JSONL 结果文件 | `data/watermarked/{dataset}_{ts}.jsonl` | 批量嵌入结果，每行一个样本 |
| 诊断 sidecar | `data/diagnostics/{stem}_block_ledger.jsonl` | 各块详细诊断，用于断点续跑对齐验证 |

#### 3.4.5 数据设计

```python
@dataclass
class KVCacheSnapshot:
    past_key_values: tuple  # Transformer KV-Cache 快照
    input_length: int       # 快照时的输入序列长度
    block_start_pos: int    # 语句块起始 token 位置

@dataclass
class GenerationResult:
    code: str
    total_blocks: int       # 总语句块数
    embedded_blocks: int    # 成功嵌入块数
    failed_blocks: int      # 嵌入失败块数
    fallback_blocks: int    # 级联兜底嵌入块数
    block_contracts: list[BlockContract]
    block_ledgers: list[dict] | None
    diagnostic_summary: dict | None
    adaptive_mode: bool
    profile_id: str | None
    alignment_summary: dict | None
```

JSONL 每行字段：`id`, `dataset`, `prompt`, `generated_code`, `blocks`, `total_blocks`, `embedded_blocks`, `failed_blocks`, `fallback_blocks`, `embed_rate`, `watermark_params`, `diagnostics_ledger_rows`。

#### 3.4.6 算法和流程

**动态裕度：**

$$m = m_{\text{base}} + \alpha \cdot H_{\text{Node}}(N), \quad H_{\text{Node}}(N) = \frac{1}{k}\sum_{i=1}^{k}\left(-\sum_{v \in C(p_i)} P(v|p_i)\log_2 P(v|p_i)\right)$$

**LSH 方向向量派生：**

```
seed = HMAC-SHA256(secret_key, parent_node_type)   # use_ordinal_keying=False
seed = HMAC-SHA256(secret_key, parent_type:ordinal) # use_ordinal_keying=True
rng = numpy.default_rng(seed_int)
v = rng.standard_normal([lsh_d, embed_dim]); v /= ||v||
t = seed_int % 2   # 目标位 {0,1}
```

**嵌入主循环：**

```
for token in LLM_generate(prompt):
    feed to tree-sitter incremental parser
    if simple_block_closed:
        v, t = derive_direction(secret_key, parent_type)
        m = compute_margin(block_entropy)
        for attempt in range(max_retries):
            u = encoder.encode(block_text)
            p = cos(u, v); t* = 2*t - 1
            if sign(p) == t* and |p| > m: record; break
            kv_cache.rollback(snapshot); regenerate
        else if enable_cascade:
            wait for parent complex block; retry whole block
        else: record as failed
```

| 函数名 | 所在文件 | 功能 | 参数 | 返回值 |
|--------|---------|------|------|--------|

| `SemanticChannel.check` | `watermark/semantic_channel.py` | 语义投影检验 | `block_text, v, t, m` | `bool` |

### 3.5 水印提取与验证模块（`wfcllm/extract/`）

#### 3.5.1 设计图

```
待测代码 → AST 解析 → 语句块提取
        │
        ▼ 重建 v_i, t_i（与嵌入时相同逻辑）
        ▼
BlockScorer：u_i = encoder(block_i)，p_i = cos(u_i,v_i)，S_i=1/0
        │
        ▼
DPSelector：OPT(i) = max(S_i, Σ OPT(children))
        │ 自顶向下回溯，选 M 个独立块
        ▼
HypothesisTester：Z = (X - M/2) / sqrt(M/4)
        │ Z > fpr_threshold 且 M ≥ min_blocks
        ▼
DetectionResult（is_watermarked, z_score, ...）
```

#### 3.5.2 功能描述

在不依赖原始代码的情况下，从待测代码中提取水印并完成统计学判决。DP 去重消除 AST 嵌套的统计相关性，保证 Z-score 检验的 i.i.d. 前提。

#### 3.5.3 输入数据

| 数据项 | 来源 | 格式 | 有效性规则 |
|--------|------|------|-----------|
| 待测代码 | 用户输入或 JSONL 文件 | Python 代码字符串 | 可被 tree-sitter 解析 |
| `ExtractConfig` | 配置文件/CLI | Python dataclass | `secret_key` 与嵌入时一致 |
| `BlockContract` 列表（可选） | 嵌入时的 JSONL | JSON 数组 | 自适应检测模式下必须提供 |

#### 3.5.4 输出数据

| 数据项 | 格式 | 说明 |
|--------|------|------|
| `DetectionResult` | Python dataclass | `is_watermarked`, `z_score`, 各块详情 |
| 检测报告 | JSON 文件（批量模式） | TPR/FPR 统计、Z-score 分布直方图 |

#### 3.5.5 数据设计

```python
@dataclass
class DPNode:
    block_id: str
    score: int          # S_i：1（命中）或 0（未命中）
    opt_value: int      # OPT(i)：DP 最优值
    children: list[str] # 子节点 block_id 列表
    selected: bool      # 是否被选为独立样本
```

校准阈值存储路径：`data/calibration/threshold_{dataset}.json`，格式：`{"z_threshold": 3.5, "fpr": 0.001}`。

#### 3.5.6 算法和流程

**DP 去重：**

$$\text{OPT}(i) = \max\left(S_i,\ \sum_{j \in \text{children}(i)} \text{OPT}(j)\right)$$

自底向上计算，自顶向下回溯选取互不嵌套的独立样本集。

**Z-score 假设检验：**

$$Z = \frac{X - M/2}{\sqrt{M/4}}, \quad Z > \text{fpr\_threshold} \land M \ge \text{min\_blocks} \Rightarrow \text{含水印}$$

零假设：自然编写代码的命中概率 = 0.5（即 $X \sim B(M, 0.5)$）。

#### 3.5.7 函数说明

| 函数名 | 所在文件 | 功能 | 参数 | 返回值 |
|--------|---------|------|------|--------|
| `ExtractPipeline.detect` | `extract/pipeline.py` | 完整检测流程 | `code: str, config` | `DetectionResult` |
| `BlockScorer.score_blocks` | `extract/scorer.py` | 批量语义打分 | `blocks: list[StatementBlock]` | `list[BlockScore]` |
| `DPSelector.select` | `extract/dp_selector.py` | DP 去重 | `block_scores, ast_tree` | `list[BlockScore]` |
| `HypothesisTester.test` | `extract/hypothesis.py` | Z-score 检验 | `selected, threshold` | `DetectionResult` |
| `CalibrationRunner.run` | `extract/calibration/runner.py` | 校准 FPR 阈值 | `negative_corpus, config` | `float` |
| `AlignmentChecker.check` | `extract/alignment.py` | 验证嵌入/提取对齐 | `contracts, detected_blocks` | `AlignmentReport` |

#### 3.5.8 全局数据结构与该模块的关系

- 读取：`ExtractConfig`（检测参数）；`BlockContract`（自适应模式，从 JSONL 反序列化）
- 共享：`build_block_contracts()`（`common/block_contract.py`）
- 写入：`DetectionResult`（传给评估模块）

### 4.3 内部接口

#### 4.3.1 接口说明

**编码器模块 → 水印嵌入/提取模块（语义向量接口）：**

水印嵌入模块和提取模块均通过 `SemanticEncoder.encode()` 获取代码块的语义向量。编码器实例在模块初始化时加载，跨语句块复用，避免重复加载模型权重。

**语言适配层 → 水印嵌入模块（AST 解析接口）：**

`WatermarkInterceptor` 调用 `extract_statement_blocks()` 对实时生成的代码进行增量解析，检测简单语句块闭合事件。

**公共数据契约（嵌入端 ↔ 提取端）：**

`build_block_contracts()` 函数在嵌入端和提取端均被调用，保证两端使用完全相同的语句块分割逻辑和契约字段，是系统一致性的关键保证。

**水印嵌入 → 评估模块（结果接口）：**

`WatermarkPipeline.run()` 返回 JSONL 文件路径，`BenchmarkRunner` 读取该文件进行功能正确性评测；`ExtractPipeline.detect()` 读取同一文件中的 `BlockContract` 进行水印检测。

## 5. 数据库设计

本系统不使用关系型数据库。所有结构化数据以 **JSONL（JSON Lines）** 格式存储于文件系统，每行一个 JSON 对象，支持流式读写与断点续跑。

**主要数据文件：**

| 文件路径 | 内容 | 读写方式 |
|---------|------|---------|
| `data/watermarked/{dataset}_{ts}.jsonl` | 水印嵌入结果（生成代码、块契约、嵌入统计） | 追加写，流式读 |
| `data/diagnostics/{stem}_block_ledger.jsonl` | 各块诊断数据（用于断点续跑对齐验证） | 追加写，流式读 |
| `data/results/{dataset}_{ts}_details.jsonl` | 基准评测详细结果（每题通过/失败） | 追加写 |
| `data/results/{dataset}_{ts}_summary.json` | 基准评测汇总统计（pass@k、嵌入率均值） | 覆盖写 |
| `data/checkpoints/encoder/` | 编码器训练检查点（每 epoch 一个） | PyTorch save/load |
| `data/models/encoder/` | 最优编码器权重 | PyTorch save/load |
| `data/calibration/threshold_{dataset}.json` | FPR 校准阈值 | 覆盖写，单次读 |
| `configs/base_config.json` | 默认运行配置 | 只读 |

**断点续跑机制：** `common/checkpoint.py` 中的 `load_processed_ids()` 读取已完成样本 ID 集合（`set[str]`），`resolve_resume_path()` 自动识别最新输出文件作为恢复起点。恢复时验证诊断 sidecar 与主文件的块序号对齐完整性，防止数据不一致。

**安全约束：** 密钥（`secret_key`）不写入任何持久化文件，JSONL 结果文件中仅记录公开水印参数（`lsh_d`、`lsh_gamma`、`margin_base`、`margin_alpha`）。

## 6. 系统出错处理

### 6.1 出错信息

| 错误类型 | 触发条件 | 输出信息形式 | 含义 | 处理方式 |
|---------|---------|------------|------|---------|
| `ValueError: dataset must be one of ...` | `WatermarkPipelineConfig` 传入不支持的数据集名 | Python 异常 | 数据集名称不在 `SUPPORTED_DATASETS` 中 | 检查 `--dataset` 参数，使用 `humaneval` 或 `mbpp` |
| `ValueError: Resume file does not match dataset` | 断点续跑文件与当前数据集不匹配 | Python 异常 | 续跑文件名前缀与数据集名不一致 | 检查 `--resume` 参数指向的文件是否属于当前数据集 |
| `ValueError: Resume diagnostics sidecar missing` | 续跑时诊断 sidecar 文件不存在 | Python 异常 | 主文件存在但诊断文件缺失，数据不完整 | 删除不完整的续跑文件，重新从头运行 |
| `ValueError: Resume diagnostics sidecar is not aligned` | 诊断文件与主文件块序号不对齐 | Python 异常 | 续跑数据损坏，块记录不完整 | 同上，重新运行 |
| `RuntimeError: CUDA out of memory` | GPU 显存不足 | PyTorch 异常 | 模型或批次过大 | 减小 `batch_size`，或降低 `max_new_tokens` |
| `tree_sitter.ParseError` | 代码语法错误，无法解析 | Python 异常 | 待测代码不是合法 Python | 检查输入代码语法 |
| `FileNotFoundError: encoder model not found` | 编码器权重路径不存在 | Python 异常 | 模型未训练或路径配置错误 | 先运行 `train` 子命令，或检查 `encoder_model_path` |
| 嵌入失败（`failed_blocks > 0`） | 重试耗尽且级联兜底也失败 | stderr 警告行 | 该块无法满足水印条件 | 正常情况，记录为 `failed_block`，不影响其他块 |
| Z-score 低于阈值（`is_watermarked=False`） | 独立块数不足或命中率低 | `DetectionResult` 字段 | 水印未被检测到（可能被攻击或代码过短） | 检查 `independent_blocks` 是否 ≥ `min_blocks` |

### 6.2 补救措施

**断点续跑：** 水印嵌入过程中断后，使用 `--resume` 参数指定已有输出文件路径，系统自动跳过已处理样本，从中断处继续。

**显存不足恢复：** 若出现 CUDA OOM，系统在每次回滚后调用 `torch.cuda.empty_cache()`（间隔由 `cuda_empty_cache_interval` 控制）。若仍 OOM，可降低 `retry_token_budget` 或 `max_new_tokens` 参数后重新运行。

**模型加载失败恢复：** 若本地模型路径不存在，系统会尝试从 HuggingFace Hub 下载（需网络）。离线环境下需预先通过 `tools/download_codet5.py` 下载模型到 `data/models/codet5-base/`。

**校准阈值缺失：** 若 `data/calibration/threshold_{dataset}.json` 不存在，系统使用默认值 `fpr_threshold=3.0`（占位值）。正式使用前应运行 `calibrate` 子命令生成准确阈值。

**数据集离线验证：** 运行 `tools/verify_all_offline.py` 可验证所有本地模型和数据集是否完整，在部署前排查缺失文件。

## 7. 其他设计

### 7.1 安全设计

- **密钥隔离**：`secret_key` 仅在运行时通过 CLI 参数或环境变量传入，不写入任何持久化文件
- **水印不可见性**：水印通过语义特征的统计偏置实现，不修改代码语法结构，生成代码与未加水印代码在表面上无法区分
- **抗等价变换攻击**：语义编码器的对比学习训练保证对变量重命名、控制流改写、格式调整等等价变换的不变性
- **抗删除攻击**：DP 去重后的独立样本集在部分块被删除后仍可维持统计显著性（Z-score 随独立块数降低而下降，但不会突然失效）
- **抗替换攻击**：Z-score 检验基于多块统计，单块替换对整体 Z-score 影响有限

### 7.2 性能设计

- **GPU 并行**：语义编码器推理和 LLM 生成均在 GPU 上执行，利用 CUDA 并行计算加速
- **KV-Cache 复用**：通过保存语句块起始位置的 KV-Cache 快照，回滚时无需重新计算前缀的注意力，大幅减少重试开销
- **编码器批处理**：提取阶段对多个语句块批量调用编码器，减少 GPU 调度开销
- **自适应重试温度**：`retry_temperature_schedule` 允许在不同重试轮次使用不同采样温度，前几次用低温度（高确定性）快速尝试，后几次用高温度（高多样性）增加成功概率

### 7.3 内存管理

- **CUDA 显存**：每处理 `cuda_empty_cache_interval`（默认 10）个语句块后调用 `torch.cuda.empty_cache()` 释放显存碎片
- **KV-Cache 快照**：每次回滚后释放旧快照引用，避免多个快照同时占用显存
- **重试预算**：`retry_token_budget` 参数限制每次重试的最大 token 数（默认 `max_new_tokens // 2`），防止单次重试消耗过多显存
- **流式 JSONL 写入**：结果文件采用追加写模式，每处理一个样本立即 flush，避免大量数据积压在内存

### 7.4 可扩展性设计

- **多语言扩展**：`lang/` 目录下已预留 `cpp/`、`java/`、`js/` 子包，通过 `LangAdapter` 工厂模式注册新语言解析器，无需修改核心水印逻辑
- **变换规则扩展**：`TransformEngine` 基于 `Registry[T]` 泛型注册表，新增变换规则只需继承 `BaseTransformRule` 并注册，符合开闭原则
- **数据集扩展**：`datasets/adapter.py` 定义统一适配器接口，新增数据集只需实现 `load_prompts()` 方法并在 `registry.py` 中注册

### 7.5 测试策略

- **单元测试**：覆盖各变换规则、AST 解析、LSH 计算、DP 选择器等核心算法（`tests/` 目录）
- **集成测试**：覆盖完整的水印嵌入→提取→检测流水线，验证端到端正确性（`tests/integration/` 目录）
- **离线约束**：所有测试通过 `HF_HUB_OFFLINE=1` 环境变量强制使用本地模型和数据集，禁止网络访问
- **运行命令**：`HF_HUB_OFFLINE=1 conda run -n WFCLLM pytest tests/ -v`
