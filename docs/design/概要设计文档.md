# WFCLLM 概要设计文档

> 项目全称：基于语句块语义特征的生成时代码水印系统（WaterMark for Code LLM）

---

## 1. 系统概述

### 1.1 系统简介

WFCLLM（WaterMark for Code LLM）是一个面向大语言模型（LLM）生成代码的**生成时不可见水印系统**。随着 GPT-4、CodeLlama 等代码大模型的广泛应用，AI 生成代码的溯源与确权成为重要问题。本系统在 LLM 生成代码的过程中，以代码抽象语法树（AST）的语句块为最小嵌入单元，利用预训练语义编码器提取语义特征，通过拒绝采样机制将水印信息隐式嵌入生成代码，并在检测端通过统计假设检验完成无参考水印验证。

**核心术语说明：**

| 术语 | 说明 |
|------|------|
| 语句块（Statement Block） | AST 中的最小可嵌入单元，分为简单语句块（simple）和复杂语句块（complex） |
| 语义编码器（Semantic Encoder） | 基于 CodeT5 对比学习微调的代码语义特征提取模型，输出 128 维向量 |
| LSH 方向向量 | 由密钥与 AST 局部拓扑哈希派生的伪随机单位向量，决定水印嵌入方向 |
| 拒绝采样（Rejection Sampling） | 对不满足水印条件的代码块触发重新生成，直至满足条件或达到重试上限 |
| KV-Cache 回滚 | 利用 Transformer 的键值缓存机制，将生成状态回退到语句块起始位置 |
| 节点信息熵（Node Entropy） | 衡量 AST 节点生成不确定性的指标，用于动态调整水印嵌入裕度 |
| 动态规划去重（DP Dedup） | 自底向上遍历 AST，消除嵌套节点带来的统计相关性 |
| Z-score 检验 | 基于二项分布的标准化统计量，用于判断水印是否存在 |
| 自适应 Gamma（Adaptive Gamma） | 根据节点熵分位数动态调整 LSH 投影阈值 γ 的机制 |
| Token 通道（Token Channel） | 辅助水印通道，在 token 概率分布层面叠加水印信号 |

### 1.2 系统目标

**功能目标：**

1. 训练鲁棒语义编码器，使其对代码等价变换（变量重命名、控制流改写、格式调整等）具有不变性
2. 在 LLM 生成代码时，以语句块为粒度实时嵌入不可见水印，不影响代码功能正确性
3. 在不依赖原始代码的情况下，从待测代码中提取水印并完成统计学确权
4. 支持 HumanEval、MBPP 等标准代码基准的批量水印嵌入与功能正确性评测
5. 支持消融实验，量化各模块对水印性能的贡献

**性能目标：**

- 水印嵌入率（embedded_blocks / total_blocks）目标 > 80%
- 检测 Z-score > 3.0 时，误报率（FPR）< 0.13%
- 对代码等价变换攻击具有鲁棒性，检测率（TPR）保持较高水平
- 生成代码在 HumanEval pass@1 上的功能正确性损失 < 5%

## 2. 总体结构设计

### 2.1 软件结构

系统按四层架构组织，各层职责清晰、松散耦合：

```
┌─────────────────────────────────────────────────────────┐

       │               │                  │
┌──────▼──────┐ ┌──────▼──────┐ ┌────────▼────────┐
│  编码器模块  │ │ 水印嵌入模块 │ │ 水印提取模块    │
│ encoder/    │ │ watermark/  │ │ extract/        │
│             │ │             │ │                 │
│ config.py   │ │ config.py   │ │ config.py       │
│ model.py    │ │ orchestrator│ │ pipeline.py     │

│  lang/          datasets/       common/   evaluation/   │

│  │  ├─ parser   ├─ mbpp         ├─ registry.py          │
```

**模块间调用关系：**

- CLI 层通过 `runners.py` 调用编排层的 `PhaseOrchestrator`
- 编排层按阶段顺序调用编码器、水印嵌入、水印提取三个业务模块
- 水印嵌入模块通过 `lang/` 的 AST 解析器触发语句块分割
- 水印嵌入与提取模块共享 `common/block_contract.py` 中的 `BlockContract` 数据契约
- 所有业务模块通过 `datasets/` 适配层访问 HumanEval/MBPP 数据集

### 2.2 设计思想

**三阶段流水线设计：** 系统将整体任务分解为编码器预训练、生成时嵌入、提取验证三个相互独立的阶段，每个阶段有独立的配置（`EncoderConfig`、`WatermarkConfig`、`ExtractConfig`）和 Runner，支持单独运行或串联执行。

**语义通道与 Token 通道双通道设计：** 主通道（语义通道）基于代码块整体语义特征进行水印嵌入，具有较强的语义鲁棒性；辅助通道（Token 通道）在 token 概率分布层面叠加水印信号，两者可独立启用或联合使用，通过 `token_channel.mode` 参数控制。

**层次化兜底机制：** 嵌入失败时先在简单语句块级别重试（最多 `max_retries` 次），若仍失败则等待外层复杂语句块闭合后整体重试（级联回退，`enable_cascade`），保证整体嵌入率。

**离线优先设计：** 所有模型路径、数据集路径均支持本地路径配置，`HF_HUB_OFFLINE=1` 环境变量可完全禁用网络访问，确保在内网隔离环境下正常运行。

**数据契约解耦：** 嵌入端与提取端通过 `BlockContract`（不可变 dataclass）共享语句块元数据，避免两端实现耦合，同时通过 JSONL 文件持久化契约数据支持断点续跑。

## 3. 模块设计

### 3.1 语义编码器模块（`wfcllm/encoder/`）

#### 3.1.1 功能描述

本模块负责训练一个"重执行语义、轻表面结构"的代码特征提取器。以 CodeT5-base 为骨干网络，通过对比学习微调，使编码器对代码等价变换（变量重命名、控制流改写、格式调整）具有不变性，对语义破坏性变换（运算符翻转、边界偏移）具有判别性。

功能流程：
1. 从 HumanEval/MBPP 数据集中切分语句块
2. 通过 AST 变换引擎构造正样本（等价变换）和负样本（破坏性变换 + 随机无关块）
3. 以边界损失函数（Margin Loss）进行对比学习微调
4. 导出鲁棒语义编码器权重，供水印嵌入与提取模块使用

#### 3.1.2 接口描述

| 接口 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `SemanticEncoder.encode(code: str)` | 代码字符串 | `torch.Tensor [128]` | 提取 128 维语义特征向量 |
| `EncoderTrainer.train()` | `EncoderConfig` | 检查点文件 | 执行完整训练流程 |
| `EncoderEvaluator.evaluate()` | 测试集路径 | 评估指标 dict | 计算 top-k 检索准确率 |

#### 3.1.3 数据结构描述

```python
@dataclass
class EncoderConfig:
    model_name: str = "Salesforce/codet5-base"  # 或本地路径
    embed_dim: int = 128          # 输出向量维度
    use_lora: bool = True         # 是否启用 LoRA
    lora_r: int = 16              # LoRA 秩
    lora_alpha: int = 32          # LoRA 缩放系数
    lora_dropout: float = 0.1
    lora_target_modules: list[str] = ["q", "v"]
    use_bf16: bool = True         # BF16 混合精度
    data_sources: list[str] = ["mbpp", "humaneval"]
    max_seq_length: int = 256
    negative_ratio: float = 0.5   # 困难负样本比例
    lr: float = 2e-5
    batch_size: int = 64
    epochs: int = 10
    margin: float = 0.3           # 余弦边界 δ
    early_stopping_patience: int = 3
```

#### 3.1.4 实现思路

损失函数采用余弦边界损失：

$$L = \sum_{i} \max\{0,\ \delta - \cos(E(x_i), E(x_i^+)) + \cos(E(x_i), E(x_i^-))\}$$

其中 $x_i$ 为原始代码块，$x_i^+$ 为等价变换正样本，$x_i^-$ 为负样本，$\delta=0.3$ 为安全边界。LoRA 仅微调 CodeT5 的 Q/V 注意力矩阵，大幅减少可训练参数量。

#### 3.1.5 其他

以服务程序形式运行（`python -m wfcllm.encoder`），无人机交互界面，通过 CLI 参数或配置文件驱动。

### 3.2 水印嵌入模块（`wfcllm/watermark/`）

#### 3.2.1 功能描述

本模块在 LLM 生成代码的过程中实时嵌入水印。核心流程：

1. **实时拦截**：`WatermarkInterceptor` 挂载在 LLM 生成循环上，将生成的 token 序列送入 Tree-sitter 增量解析器，检测简单语句块闭合事件
2. **参数准备**：提取 AST 局部拓扑哈希（父节点类型 + 当前节点类型），结合密钥派生 LSH 方向向量 $v$ 和目标位 $t$；计算节点信息熵，得到动态裕度 $m$
3. **语义投影检验**：将代码块输入语义编码器得到向量 $u$，计算余弦投影 $p = \cos(u, v)$，验证 $\text{sgn}(p) == t^*$ 且 $|p| > m$
4. **拒绝采样**：检验失败时通过 KV-Cache 回滚重新生成，最多重试 `max_retries` 次
5. **级联兜底**：局部重试耗尽后，等待外层复杂语句块闭合，对整体重新执行步骤 2~4

#### 3.2.2 接口描述

| 接口 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `WatermarkGenerator.generate(prompt)` | 提示字符串 | `GenerationResult` | 生成带水印代码 |
| `WatermarkPipeline.run()` | `WatermarkPipelineConfig` | JSONL 文件路径 | 批量水印嵌入 |
| `SemanticChannel.check(block_text)` | 代码块文本 | `bool` | 语义投影检验 |
| `AdaptiveGammaSchedule.resolve(entropy_units)` | 熵单元数 | `GammaResolution` | 计算自适应 γ |

**`GenerationResult` 字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | `str` | 生成的代码文本 |
| `total_blocks` | `int` | 总语句块数 |
| `embedded_blocks` | `int` | 成功嵌入水印的块数 |
| `failed_blocks` | `int` | 嵌入失败的块数 |
| `fallback_blocks` | `int` | 通过级联兜底嵌入的块数 |
| `block_contracts` | `list[BlockContract]` | 各块的元数据契约 |

#### 3.2.3 数据结构描述

```python
@dataclass
class WatermarkConfig:
    secret_key: str               # 水印密钥
    encoder_model_path: str       # 语义编码器路径
    encoder_embed_dim: int = 128  # 向量维度
    margin_base: float = 0.1      # 基础裕度 m_base
    margin_alpha: float = 0.05    # 裕度缩放系数 α
    max_retries: int = 5          # 最大重试次数
    lsh_d: int = 3                # LSH 哈希函数数量
    lsh_gamma: float = 0.5        # LSH 投影阈值 γ
    enable_cascade: bool = True   # 是否启用级联兜底
    adaptive_gamma: AdaptiveGammaConfig  # 自适应 γ 配置
    token_channel: TokenChannelConfig    # Token 通道配置
```

#### 3.2.4 实现思路

动态裕度计算：$m = m_{\text{base}} + \alpha \cdot H_{\text{Node}}(N)$，其中节点熵 $H_{\text{Node}}(N) = \frac{1}{k}\sum_{i=1}^{k}\left(-\sum_{v \in C(p_i)} P(v|p_i)\log_2 P(v|p_i)\right)$。

LSH 方向向量由 HMAC-SHA256 派生：`seed = HMAC(secret_key, parent_node_type)` → 伪随机正交基 → 单位向量 $v$。

KV-Cache 回滚通过保存语句块起始位置的 `past_key_values` 快照实现，回滚时恢复快照并以不同随机种子重新采样。

#### 3.2.5 其他

以批处理服务程序形式运行，输出 JSONL 格式结果文件，支持断点续跑（`--resume` 参数）。每处理 `cuda_empty_cache_interval` 个块后调用 `torch.cuda.empty_cache()` 防止显存碎片化。

### 3.3 水印提取与验证模块（`wfcllm/extract/`）

#### 3.3.1 功能描述

本模块在不依赖原始代码的情况下，从待测代码中提取水印并完成统计学判决。核心流程：

1. **结构解析**：将待测代码解析为 AST，提取所有语句块，重构各块的目标方向向量 $v_i$ 和目标位 $t_i$
2. **语义打分**：对每个语句块计算余弦投影 $p_i = \cos(E(x_i), v_i)$，命中（$\text{sgn}(p_i) == t_i^*$）记 $S_i = 1$，否则记 $S_i = -1$
3. **DP 去重**：自底向上遍历 AST，通过 $\text{OPT}(i) = \max(S_i, \sum_{j \in \text{children}(i)} \text{OPT}(j))$ 消除嵌套节点的统计相关性
4. **独立样本提取**：自顶向下回溯 DP 状态数组，得到 $M$ 个互不嵌套的独立语句块
5. **假设检验**：计算 Z-score $= \frac{X - M/2}{\sqrt{M/4}}$，其中 $X$ 为命中次数；Z > 3.0 则判定为含水印

#### 3.3.2 接口描述

| 接口 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `ExtractPipeline.detect(code)` | 代码字符串 | `DetectionResult` | 完整检测流程 |
| `BlockScorer.score_blocks(blocks)` | 语句块列表 | `list[BlockScore]` | 批量语义打分 |
| `DPSelector.select(block_scores)` | 打分列表 | `list[BlockScore]` | DP 去重选取独立样本 |
| `HypothesisTester.test(selected)` | 独立样本列表 | `DetectionResult` | Z-score 假设检验 |
| `CalibrationRunner.run()` | 负样本语料 | 阈值文件 | 校准 FPR 阈值 |

#### 3.3.3 数据结构描述

```python
@dataclass
class BlockScore:
    block_id: str
    score: int           # 1 (命中) 或 0 (未命中)
    min_margin: float    # 最小裕度
    gamma_effective: float = 0.5
    selected: bool = False
    source_hash: str = ""  # 块文本 SHA-256，用于自适应 γ 查找

@dataclass
class DetectionResult:
    is_watermarked: bool
    z_score: float
    p_value: float
    total_blocks: int
    independent_blocks: int  # DP 去重后的独立块数 M
    hit_blocks: int          # 命中次数 X
    expected_hits: float     # 期望命中数 M/2
    variance: float          # 方差 M/4
    hypothesis_mode: Literal["fixed", "adaptive"]
    block_details: list[BlockScore]
    alignment_report: AlignmentReport | None
```

#### 3.3.4 实现思路

DP 去重的关键在于处理 AST 嵌套：若生成端在父节点触发了级联兜底注入，子节点的得分表现为随机噪声，DP 方程能自动选择父节点层级的真实水印信号，过滤子节点干扰。

自适应检测模式（`adaptive_detection.mode = "prefer-adaptive"`）下，提取端从 JSONL 元数据中读取嵌入时的 `gamma_effective` 值，使用与嵌入端完全一致的 γ 参数进行检验，提升检测精度。

#### 3.3.5 其他

校准子模块（`calibration/`）通过在大量未加水印代码上运行检测流程，统计 Z-score 分布，确定满足目标 FPR 的阈值 $M_r$，写入配置文件供检测时使用。

### 3.5 语言适配模块（`wfcllm/lang/`）

#### 3.5.1 功能描述

提供多语言 AST 解析与代码变换能力。当前主要支持 Python，预留 C++、Java、JavaScript 扩展接口。核心功能：语句块分割、正变换（等价变换，用于构造正样本）、负变换（破坏性变换，用于构造负样本）。

#### 3.5.2 接口描述

| 接口 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `extract_statement_blocks(code)` | Python 代码字符串 | `list[StatementBlock]` | AST 语句块分割 |
| `TransformEngine.apply(code, rule)` | 代码 + 变换规则 | 变换后代码 | 执行单条变换规则 |
| `LangAdapter.get_parser(lang)` | 语言标识符 | 解析器实例 | 语言适配器工厂 |

#### 3.5.3 数据结构描述

```python
@dataclass(frozen=True)
class StatementBlock:
    block_id: str          # 唯一标识符
    node_type: str         # AST 节点类型（如 "if_statement"）
    parent_id: str | None  # 父节点 ID
    block_type: str        # "simple" 或 "complex"
    source: str            # 块源代码文本
    start_line: int
    end_line: int
```

正变换规则（`transform/positive/`）包括：控制流等价改写（for↔while）、标识符重命名、API 调用等价替换、表达式逻辑等价变换、格式调整等。负变换规则（`transform/negative/`）包括：运算符翻转、边界偏移、控制流破坏、异常逻辑破坏等。

#### 3.5.4 实现思路

基于 tree-sitter 的增量解析器实现实时语句块检测。`TransformEngine` 维护变换规则注册表（`Registry[T]`），支持按类别批量应用变换，并通过 AST 节点类型过滤适用规则，避免无效变换。

本系统不使用关系型数据库。所有结构化数据以 **JSONL（JSON Lines）** 格式存储于文件系统，每行一个 JSON 对象，支持流式读写与断点续跑。

| 文件路径 | 内容 | 格式 |
|---------|------|------|

| `data/diagnostics/{stem}_block_ledger.jsonl` | 各块的诊断数据（用于调试与断点续跑对齐） | JSONL |

### 4.2 数据结构设计

**BlockContract（语句块契约，核心共享数据结构）：**

| 字段 | 类型 | 长度/精度 | 说明 |

| `ordinal` | `int` | — | 块在代码中的顺序编号（0-indexed） |

| `start_line` | `int` | — | 块起始行号 |
| `end_line` | `int` | — | 块结束行号 |
| `entropy_units` | `int` | — | 节点信息熵单元数（token 数量加权） |
| `gamma_target` | `float` | float64 | 目标 LSH 阈值 γ |

### 4.3 数据存储设计

**访问方式：** 所有数据文件通过 Python 标准文件 I/O 访问，JSONL 文件支持追加写（`mode="a"`）以实现断点续跑。

**断点续跑机制：** `common/checkpoint.py` 中的 `load_processed_ids()` 函数读取已完成的样本 ID 集合，`resolve_resume_path()` 函数自动识别最新输出文件作为恢复起点，`WatermarkPipeline` 在恢复时验证诊断 sidecar 文件与主文件的对齐完整性。

**存储安全：** 密钥（`secret_key`）不写入任何持久化文件，水印参数文件中仅记录公开参数（`lsh_d`、`lsh_gamma`、`margin_base`、`margin_alpha`）。

**索引设计：** JSONL 文件无数据库索引，通过 Python 集合（`set[str]`）在内存中维护已处理 ID 的快速查找（O(1) 查询复杂度）。

## 6. 其他设计

### 6.1 并行处理

- **GPU 并行**：语义编码器推理和 LLM 生成均在 GPU 上执行，利用 CUDA 并行计算加速
- **批量处理**：`WatermarkPipeline` 对数据集中的每个样本串行处理（受 KV-Cache 状态管理约束，无法跨样本并行），但单样本内的编码器推理支持批处理
- **消融实验并行**：`ablation/sweep.py` 支持多配置并行扫描，通过 Python `multiprocessing` 或外部调度实现

### 6.2 安全设计

- **密钥隔离**：`secret_key` 仅在运行时通过命令行参数或环境变量传入，不写入任何持久化文件（JSONL 结果文件中仅记录公开水印参数）
- **水印不可见性**：水印嵌入通过语义特征的统计偏置实现，不修改代码语法结构，生成代码与未加水印代码在表面上无法区分
- **抗攻击性**：
  - 对等价变换攻击（重命名、格式化）：语义编码器的对比学习训练保证不变性
  - 对删除攻击（删除部分代码）：DP 去重后的独立样本集仍可维持统计显著性
  - 对替换攻击（替换部分代码块）：Z-score 检验基于多块统计，单块替换影响有限

### 6.3 内存管理

- **CUDA 显存**：每处理 `cuda_empty_cache_interval`（默认 10）个语句块后调用 `torch.cuda.empty_cache()` 释放显存碎片
- **KV-Cache 管理**：`kv_cache.py` 在语句块起始位置保存 `past_key_values` 快照，回滚时恢复快照，避免重新计算前缀的 KV 值；每次回滚后释放旧快照引用
- **重试预算**：`retry_token_budget` 参数限制每次重试的最大 token 数（默认为 `max_new_tokens // 2`），防止单次重试消耗过多显存

### 6.4 可扩展性设计

- **多语言扩展**：`lang/` 目录下已预留 `cpp/`、`java/`、`js/` 子包，通过 `LangAdapter` 工厂模式注册新语言解析器，无需修改核心水印逻辑
- **变换规则扩展**：`TransformEngine` 基于 `Registry[T]` 泛型注册表，新增变换规则只需继承 `BaseTransformRule` 并注册，符合开闭原则
- **数据集扩展**：`datasets/adapter.py` 定义统一的数据集适配器接口，新增数据集只需实现 `load_prompts()` 方法并在 `registry.py` 中注册

### 6.5 测试策略

- **单元测试**：覆盖各变换规则、AST 解析、LSH 计算、DP 选择器等核心算法
- **集成测试**：覆盖完整的水印嵌入→提取→检测流水线，验证端到端正确性
- **离线测试**：所有测试通过 `HF_HUB_OFFLINE=1` 环境变量强制使用本地模型和数据集，禁止网络访问，确保在内网环境下可复现
- **运行命令**：`HF_HUB_OFFLINE=1 conda run -n WFCLLM pytest tests/ -v`
