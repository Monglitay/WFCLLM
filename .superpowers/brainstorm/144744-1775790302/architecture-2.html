把概念压到一个具体例子里

先只看一个 simple block，不看整段程序

原始 block 示例
if ok:
    return value
语义通道怎么看它
把整个 block 当成一个整体

输入编码器 → 得到语义向量 → 做 LSH / margin 检验

关心的是：
这个 block 整体语义有没有落到目标区域
词法通道怎么看它
不把整个 block 当一个整体信号

而是在 block 里面找少量“可安全改写位点”

这里比如能找到 1 个 slot：
return value 的写法位点
slot 的含义
一个 slot = 一个可重建、可判定、候选集有限的局部位点

例如这个 slot 的候选写法可能是：

1

variant A

return value

2

variant B

result = value; return result


然后密钥决定：
这个 block 的这个 slot，这次目标是 A 还是 B
嵌入端在做什么
生成完这个 block 后：
1. 找到 slot
2. 算出目标 variant（A 或 B）
3. 如果当前写法不是目标，就尝试重写/重采样让它变成目标

词法通道的单位是 slot 命中数
检测端在做什么
只看最终代码：
1. 再次找到同一个 slot
2. 用相同密钥算出目标 variant
3. 看最终代码命中了没有

所以检测不需要原始 logits，也不需要 prompt
